# Design Document: Trade Marketplace

## Overview

Trade Marketplace is a peer-to-peer marketplace platform enabling members to list products for sale and buyers to browse, organize items in a cart, and contact sellers directly. The platform uses a token-based economy (1 token = 1 RSD) for listing fees and promotions, with no direct checkout - transactions complete offline after buyer-seller communication.

### Key Design Goals

- **Scalability**: Support growing user base with efficient data access patterns
- **Cost Efficiency**: Leverage free-tier services (database, storage, notifications)
- **User Experience**: Serbian-language UI with intuitive cart and messaging flow
- **Dual Database Strategy**: Relational DB for structured data, MongoDB for documents/logs
- **SEO-Friendly**: Unique shareable URLs for all product listings

### System Boundaries

- **In Scope**: Registration, listings, cart, messaging, ratings, subscriptions, promotions, admin config
- **Out of Scope**: Payment processing, checkout flow, shipping integration (v1)

```prisma
  @@index([sellerId])
  @@index([categoryId])
  @@index([slug])

  member      Member    @relation(fields: [memberId], references: [id])
```

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system—essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Credential Verification Correctness

*For any* Member with stored credentials, login with the correct email and password should succeed, and login with any incorrect email or password should fail.

**Validates: Requirements 1.2, 1.4**

### Property 2: Session Creation on Login

*For any* successful login attempt, a valid session should be created and associated with the authenticated Member.

**Validates: Requirements 1.3**

### Property 3: Registration Validation

*For any* registration attempt, accounts should only be created when the email format is valid and the password meets strength requirements; invalid inputs should be rejected.

**Validates: Requirements 1.1, 1.5**

### Property 4: Balance Arithmetic Correctness

*For any* Member balance and any sequence of topup and fee operations, the final balance should equal the initial balance plus all topups minus all fees, and the balance should never become negative.

**Validates: Requirements 2.1, 2.3, 2.4**

### Property 5: Insufficient Balance Prevention

*For any* operation requiring tokens (listing fee, promotion), if the Member's balance is less than the required amount, the operation should fail and the balance should remain unchanged.

**Validates: Requirements 2.5, 4.3**

### Property 6: Product Required Fields Validation

*For any* product creation attempt, the product should only be created when all required fields (name, category, price, description) are provided and valid; missing or invalid fields should cause rejection.

**Validates: Requirements 3.1, 3.4**

### Property 7: Product Image Count Validation

*For any* product creation or update, the operation should succeed only when the image count is between 1 and 5 inclusive; 0 images or more than 5 images should be rejected.

**Validates: Requirements 3.2**

### Property 8: Unique Product URL Generation

*For any* two distinct products created in the system, their generated slugs/URLs should be different.

**Validates: Requirements 3.3**

### Property 9: Listing Fee Calculation

*For any* Seller, the first N products (where N = Free_Tier_Limit, default 15) should be created without token deduction, and each subsequent product should deduct exactly Listing_Fee tokens (default 10) from the Seller's balance.

**Validates: Requirements 4.1, 4.2, 4.4**

### Property 10: Product Activation State Toggle

*For any* product, toggling its activation state should change isActive from true to false or vice versa, and the change should persist.

**Validates: Requirements 5.1**

### Property 11: Inactive Products Hidden from Search

*For any* search query, the results should never contain products where isActive is false.

**Validates: Requirements 5.2, 11.4**

### Property 12: Cart Item Addition and Removal

*For any* product added to a cart, it should appear in the cart contents, and after removal, it should no longer appear in the cart contents.

**Validates: Requirements 6.1, 6.4**

### Property 13: Cart Seller Grouping

*For any* cart containing products from multiple sellers, items should be grouped such that all items from the same seller appear in the same group, and items from different sellers appear in different groups.

**Validates: Requirements 6.2**

### Property 14: Cart Price Calculation

*For any* seller group in a cart, the displayed subtotal should equal the sum of (price × quantity) for all items in that group.

**Validates: Requirements 6.6**

### Property 15: Cart Persistence Round Trip

*For any* logged-in Member's cart contents, after session termination and re-authentication, the cart should contain the same items as before.

**Validates: Requirements 6.5**

### Property 16: Message Product References

*For any* message sent from the cart view with selected products, the created message should contain references to all selected products including their IDs, names, prices, and image URLs.

**Validates: Requirements 7.1, 7.2**

### Property 17: Conversation Threading

*For any* two Members exchanging messages, all messages between them should be retrievable in a single conversation thread, ordered by creation time.

**Validates: Requirements 7.3, 7.5**

### Property 18: Rating Validation

*For any* rating submission, it should only succeed when stars is between 1 and 5 inclusive AND a non-empty comment is provided; missing or invalid values should be rejected.

**Validates: Requirements 8.1**

### Property 19: Rating Order Enforcement

*For any* completed transaction, the Seller should only be able to submit a rating for the Buyer after the Buyer has submitted a rating for the Seller.

**Validates: Requirements 8.2, 8.3, 8.4**

### Property 20: Rating Average Calculation

*For any* Member with ratings, the displayed average rating should equal the arithmetic mean of all star values received, rounded appropriately.

**Validates: Requirements 8.5**

### Property 21: Subscription Creation and Deletion

*For any* Buyer subscribing to a Seller, the subscription should be created and retrievable, and after unsubscribing, the subscription should no longer exist.

**Validates: Requirements 9.1, 9.6**

### Property 22: Subscriber Notification on New Product

*For any* Seller with subscribers, when the Seller creates a new product, a notification should be created for each subscribed Buyer.

**Validates: Requirements 9.2**

### Property 23: Default Notification Settings

*For any* newly registered Member, all notification channels (email, SMS, Viber, WhatsApp) should be disabled by default.

**Validates: Requirements 9.4**

### Property 24: Promotion Cost Deduction

*For any* product promotion, exactly 300 tokens (or configured Promotion_Cost) should be deducted from the Seller's balance.

**Validates: Requirements 10.1**

### Property 25: Promotion Limit Enforcement

*For any* Seller with 3 promoted products, attempting to promote a 4th product should fail and leave the Seller's balance unchanged.

**Validates: Requirements 10.2**

### Property 26: Promoted Products in Search Results

*For any* search query returning results, all promoted products matching the query should appear before all non-promoted products.

**Validates: Requirements 10.3, 11.5**

### Property 27: Search Keyword Matching

*For any* keyword search, all returned products should contain the search term in their name or description.

**Validates: Requirements 11.1**

### Property 28: Search Category Filtering

*For any* search filtered by category, all returned products should belong to the specified category.

**Validates: Requirements 11.2**

### Property 29: Search Result Sorting

*For any* search with a sort parameter, the results should be ordered according to the specified criterion (price ascending, price descending, date, or relevance).

**Validates: Requirements 11.3**

### Property 30: Search Pagination

*For any* paginated search, the number of results per page should not exceed the specified limit, and navigating through pages should cover all matching results without duplicates.

**Validates: Requirements 11.6**

### Property 31: Seller Profile Product Listing

*For any* Seller profile, all products displayed should be active products owned by that Seller, and all active products owned by that Seller should be displayed.

**Validates: Requirements 12.2**

### Property 32: Product Edit Persistence

*For any* product edit operation, the updated fields should be persisted and retrievable with the new values.

**Validates: Requirements 12.3**

### Property 33: Admin Configuration Modification

*For any* admin configuration change (Free_Tier_Limit, Listing_Fee, Promotion_Cost), the new value should be persisted and used in subsequent operations.

**Validates: Requirements 15.1, 15.2, 15.3**

### Property 34: Admin Member Management

*For any* admin action to suspend or activate a Member, the Member's status should change accordingly and persist.

**Validates: Requirements 15.6**

### Error Handling Strategy

1. **Validation Errors**: Return 400 with specific field information
2. **Authentication Errors**: Return 401/403 with generic messages (security)
3. **Not Found Errors**: Return 404 with resource type
4. **Business Logic Errors**: Return 400/402 with user-friendly Serbian messages
5. **Server Errors**: Return 500 with generic message, log details internally

## Testing Strategy

### Dual Testing Approach

This project uses both unit tests and property-based tests for comprehensive coverage:

- **Unit Tests**: Verify specific examples, edge cases, and integration points
- **Property Tests**: Verify universal properties across randomly generated inputs

### Testing Framework

| Type | Framework | Purpose |
|------|-----------|---------|
| Unit Tests | Jest + React Testing Library | Component and API testing |
| Property Tests | fast-check | Property-based testing |
| E2E Tests | Playwright | Critical user flows |
| API Tests | Supertest | API endpoint testing |

### Property-Based Testing Configuration

```typescript
// jest.config.js
```
